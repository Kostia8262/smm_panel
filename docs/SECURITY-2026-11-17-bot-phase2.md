## Находки

### С1. Средне — вебхук доверяет любому секрету любого проекта; проект выбирается по id из тела
- Где: `src/bot/webhook.js:31-42` (`signatureValid` перебирает все `appSecrets()`), `src/bot/dialogs.js:64-72`
  (`appSecrets` — секреты всех проектов + `META_APP_SECRET`), `dialogs.js:173` (`projectForAccount` по `recipient.id`/`entry.id`).
- Шаги: проекту «Школа» — свой Facebook-аппсекрет S2; событие на Instagram «Школы» подписать секретом S1 «Академии».
- Ожидал: 401 — S1 не может подписывать события чужого аккаунта. Получил: 200, диалог в проекте school,
  план ответа от имени школы; поддельный echo тем же S1 переводит живой диалог школы на «человека» (бот замолкает).
- Последствия: подставные диалоги и заявки в CRM от имени любого проекта, снятие бота с диалогов, попытки Send API токеном чужой страницы.
- Подтверждено: тест-атаки 1 и 2 падают (`AssertionError: чужой секрет принят: HTTP 200, диалог #1 в проекте 2`).
- Чинить: возвращать из проверки подписи, *каким* секретом подписано, и принимать только события, где
  `projectForAccount(...)` даёт проект с этим же секретом (`META_APP_SECRET` — по явному списку). Найдено: разбором и атакой.

### С2. Средне — переписка и ПДн хранятся бессрочно
- Где: таблицы `bot_messages`, `bot_dialogs` (`phone`, `contact_name`, `child_age`, `preferred_time`), `bot_reply_plans.text`.
  `grep -rn "DELETE FROM bot_" src` — 0; `src/retention.js` чистит только файлы кадров.
- Риск: утечка базы/бэкапа отдаёт всю историю переписки с родителями; заявка уже в CRM — копия в панели не нужна.
- Чинить (решение владельца): срок, например 90 дней после последнего сообщения — тексты в `bot_messages` удалять
  или обезличивать, телефон в диалоге стирать после `lead_status='sent'`. Найдено: разбором.

### Г1. Гигиена — CSRF с соседних поддоменов на POST без тела
- `POST /api/bot/dialogs/:id/{send-draft,return,lead}` не читают тело и не сверяют `Origin`. Cookie `SameSite=Lax`
  (`src/auth.js:78`) не спасает от same-site: `python.`, `roblox.`, `dev.`, `child.mycomputer.education` — тот же сайт.
- Стенд: `curl -b <owner> -X POST -H 'Origin: https://python.mycomputer.education' -H 'content-type: text/plain'
  …/dialogs/1/lead` → 200, заявка ушла в приёмник; `…/return` → 200. `reply` не берётся (нужен JSON → preflight).
- Нужна XSS на любом из сайтов сети. Чинить: общий middleware — для не-GET под `/api/` требовать
  `Origin`/`Sec-Fetch-Site: same-origin` (или `content-type: application/json`). Касается всей панели, не только бота.

### Г2. Гигиена — ответы вебхука без заголовков безопасности
- `mountMetaWebhook` стоит до middleware с CSP/nosniff (`src/server.js:57-58` против `:84`). Стенд: `GET
  /webhooks/meta?…&hub.challenge=<html><script>…` → 200 `text/plain`, тело отражено, `X-Content-Type-Options` нет.
  Без verify token не воспроизводится, браузеры `text/plain` не исполняют — гигиена. Чинить: заголовки до вебхука
  (они не трогают тело) или `nosniff` в самом вебхуке.

### Г3. Гигиена — ключ CRM уходит по любому адресу, в том числе `http://`
- `PUT /api/settings/leads` (только владелец) пишет `leads_api_url` без проверки; ключи остаются прежними.
  Стенд: URL → `http://127.0.0.1:3392`, «Повторить заявку» → приёмник получил `POST /api/leads/admin` с `x-admin-token` (20 знаков).
  SSRF владельцем — не граница; риск — сменённый адрес утягивает сохранённые ключи. Чинить: только `https://` и
  домены из `own_domains`; при смене адреса сбрасывать `leads_api_token`/`crm_leads_write_token`.

- IDOR между проектами: `openDialog/humanReply/retryLead/returnToBot` с чужим `projectId` → «не найден» (атака 4).
  Сотрудники не разделены по проектам вообще (`currentProjectId` = `?project=`) — модель панели, не находка.
- Подпись: без заголовка и с подписью другого тела → 401 (атака 5); сравнение `timingSafeEqual`, перебор без раннего выхода.
- Verify token: 18 случайных байт, сравнение по хешу за постоянное время; СММщику не отдаётся (`routes.js:34-38`).
- Сырой парсер только на `POST /webhooks/meta` (`webhook.js:62`), общий `express.json` после него (`server.js:62`).
- Тело заявки CRM: `JSON.stringify`, `source`/`utm_*` из кода — подмена через `preferred_time` с `"}, "source":"evil` не прошла
  (стенд, приёмник получил `source: ig_dm`). Имя — `parseName` берёт только буквы; CRM дополнительно режет `<>` (`sanitize`).
- Текст клиента не попадает в ответы бота: реплики только из `bot_replies`, подстановка одна — `{age}` (число).

- Склейка/флуд: один план на диалог (уникальный индекс), новое сообщение сдвигает время; вебхук без подписи не пишет ничего.
