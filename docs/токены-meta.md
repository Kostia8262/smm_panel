# Токены Instagram, Facebook и Threads — по шагам

Инструкция под аккаунты **«Мой компьютер»** (академия).

**С 13.09.2026 токены получаются кнопками в панели** — «Подключить через
Facebook» и «Подключить через Threads» в карточке проекта. Руками в кабинете Meta
остаётся только разовая настройка приложения (разделы 0 и 1 и адреса возврата).
Ручные пути через Graph API Explorer и генератор оставлены ниже как запасные.

Место хранения: **`.env` для площадок не нужен**. Токены лежат в карточке
проекта («Проекты» → проект), в базе — шифротекстом, ключ — `data/secret.key`.

Три площадки — **два разных токена**:

| Площадка | Откуда токен | Срок |
|---|---|---|
| Facebook | токен страницы, кнопкой «Подключить через Facebook» | **бессрочный** (взят через долгоживущий токен пользователя) |
| Instagram | **тот же токен страницы**, та же кнопка | тот же |
| Threads | свой вход, кнопкой «Подключить через Threads» | 60 дней, **продлевается сам** |

У токенов Meta есть и **второй срок — доступ к данным** (правило «90 дней без
входа в приложение»). Про него — раздел 5.

## 0. Привести аккаунты в состояние, при котором API вообще работает

Без этого шага всё остальное упрётся в невнятные ошибки.

1. **Instagram «Мой компьютер» → Professional (Business).**
   Приложение Instagram → Настройки → Тип аккаунта → «Переключиться на
   профессиональный» → **Бизнес** (Creator тоже публикует, но с Business
   меньше сюрпризов с правами).
2. **Связать Instagram со страницей Facebook «Мой компьютер».**
   Проще из Meta Business Suite: `business.facebook.com` → Настройки →
   Аккаунты → Аккаунты Instagram → Добавить → связать со страницей.
   С личного профиля Facebook API не публикует вовсе — нужна именно **страница**.
3. **Бизнес-портфель (Business Manager).** Страница и Instagram должны лежать
   в одном портфеле — иначе системный пользователь из шага 2Б их не увидит.

Проверка шага: в Business Suite видно и страницу, и Instagram под одним
портфелем, и на обоих у вас роль администратора.

## 1. Приложение в кабинете разработчика

1. `developers.facebook.com` → «Мои приложения» → **Создать приложение**.
2. Тип — **Business** (формулировки Meta меняет; нужен тот тип, где доступны
   «Страницы» и «Instagram»).
3. Название — например `MyComputer SMM`. Почта — рабочая: на неё придут письма
   о протухании токенов и о нарушениях.
4. **Роли → Разработчики/Администраторы**: добавить свой аккаунт, если его там
   нет. Это ключ ко всему — **пока приложение в режиме разработки, оно работает
   для аккаунтов, у которых есть роль в нём же**. Публикуем в свои аккаунты →
   проверка Meta не нужна.
5. Продукты → добавить **Instagram** (Instagram Graph API) и, для шага 3,
   **Threads API** (это отдельный use case).
6. Настройки → Основное: записать **ID приложения** и **Секрет приложения** —
   панель ими читает срок жизни токена (`debug_token`).

## 2. Facebook + Instagram: один токен на обе площадки

### Основной путь — кнопка «Подключить через Facebook»

Один раз в кабинете Meta:

1. `developers.facebook.com` → **MyComputer SMM** → **Вход через Facebook для
   бизнеса** → **Настройки** → поле **«Действительные URI перенаправления для
   OAuth»** → вписать и нажать Enter:
   ```
   https://smm.mycomputer.education/oauth/facebook
   ```
   → **Сохранить изменения**. Проверить тем же адресом в «Средство проверки URI
   переадресации» вверху страницы. Переключатели не трогать: клиентская и
   веб-авторизация OAuth — «Да», строгий режим — «Да».
2. В панели в карточке **Facebook** заполнить **ID приложения** и **Секрет
   приложения** (кабинет Meta → Настройки приложения → Основное).

Дальше — в панели:

3. Карточка Facebook или Instagram → **«Подключить через Facebook»** → войти.
4. **Экран выбора страницы.** По каждой странице видно: бессрочный ли токен,
   привязан ли Instagram, можно ли на неё заменить. **Пока не нажато
   «Применить», ничего не меняется.** Если экран не открылся — обновить
   страницу панели через **Ctrl+F5** (браузер держит старую версию) и войти заново.
5. Выбрать страницу → **«Применить»**. Панель сама пишет ID страницы и её
   токен в карточку Facebook, **Instagram находит по странице** и пишет туда же.

Защита, которую кнопка не обходит:
- **бессрочный токен срочным не заменяется**, срочный не ставится вовсе;
- прав у нового токена не меньше, чем у нынешнего рабочего;
- нужны права публикации и удаления и право страницы «создавать контент»;
- **другая страница — только с галочкой подтверждения**;
- прежние доступы перед заменой уходят в **резервную копию**. Вернуть:
  `node tools/set-account.mjs --project 1 --platform facebook --restore`
  (`--backups` — список копий). Instagram — то же с `--platform instagram`.

**Конфигурация входа** (Вход через Facebook для бизнеса → Конфигурации) для
академии **не понадобилась** — вход прошёл со списком прав. Если окно Facebook
откажет с ошибкой про конфигурацию: создать её (тип токена — пользовательский,
права — как в разделе 2А, плюс `instagram_manage_contents`) и вписать её ID в
поле карточки **«ID конфигурации входа»**.

Незавершённый вход (закрыли экран выбора) виден без токенов:
`node tools/oauth-pending.mjs --project 1`.

### 2А. Запасной путь — Graph API Explorer

1. `developers.facebook.com/tools/explorer`.
2. Сверху выбрать своё приложение, тип токена — **User Token**.
3. Добавить разрешения (каждое через «Add a Permission»):
   - `pages_show_list`
   - `pages_manage_posts`
   - `pages_read_engagement`
   - `instagram_basic`
   - `instagram_content_publish`
   - `business_management`
4. **Generate Access Token** → в окне входа отметить страницу «Мой компьютер»
   и связанный Instagram. Если страницы в списке нет — вернуться к шагу 0.
5. Узнать ID страницы и её токен — запрос `GET /me/accounts`. В ответе у нужной
   страницы: `id` — это **ID страницы**, `access_token` — токен страницы
   (пока короткий).

6. Обменять на долгоживущий. Сначала пользовательский токен:

```
curl "https://graph.facebook.com/v26.0/oauth/access_token?grant_type=fb_exchange_token&client_id=APP_ID&client_secret=APP_SECRET&fb_exchange_token=КОРОТКИЙ_USER_TOKEN"
```

   Затем **повторить `/me/accounts` уже с долгоживущим пользовательским
   токеном** — выданный так токен страницы срока не имеет (живёт, пока не
   сменён пароль и не отозваны права):

```
curl "https://graph.facebook.com/v26.0/me/accounts?access_token=ДОЛГИЙ_USER_TOKEN"
```

7. Узнать ID Instagram-аккаунта:

```
curl "https://graph.facebook.com/v26.0/PAGE_ID?fields=instagram_business_account&access_token=PAGE_TOKEN"
```

   В ответе `instagram_business_account.id` — это **ID аккаунта Instagram**
   (числовой, обычно начинается с 17…; это не имя пользователя).

### 2Б. Системный пользователь — токен, не зависящий от вашего пароля

Кнопка даёт бессрочный токен, но он привязан к **вашему** аккаунту: сменили
пароль Facebook или вышли из всех сеансов — токен сброшен (сторож поймает это
живой проверкой). Токен системного пользователя привязан к служебной учётке
бизнеса, и смена вашего пароля его не рвёт. Делать, если пароль меняется часто
или доступ передаётся другим людям.

1. `business.facebook.com` → **Настройки бизнеса** → Пользователи →
   **Системные пользователи** → Добавить. Имя — `smm-panel`, роль —
   **Администратор**.
2. У созданного пользователя → **Добавить активы**:
   - Страницы → «Мой компьютер» → **полный доступ к контенту**,
   - Аккаунты Instagram → «Мой компьютер» → полный доступ,
   - Приложения → `MyComputer SMM` → полный доступ.
3. **Создать новый токен** → выбрать приложение → **срок действия «Никогда»** →
   отметить скоупы: `pages_manage_posts`, `pages_read_engagement`,
   `instagram_basic`, `instagram_content_publish`, `business_management`.
4. **Токен показывается ровно один раз.** Скопировать сразу и положить туда же,
   где остальные доступы проекта.
5. ID страницы и ID Instagram берутся теми же двумя запросами из 2А (шаги 5 и 7),
   уже с этим токеном.

### Проверить токен до того, как вписывать

```
curl "https://graph.facebook.com/v26.0/debug_token?input_token=PAGE_TOKEN&access_token=APP_ID|APP_SECRET"
```

Смотреть: `is_valid: true`; `expires_at: 0` — бессрочный; в `scopes` есть
`pages_manage_posts`, `instagram_content_publish`, `instagram_manage_contents`;
`data_access_expires_at` — второй срок (раздел 5).

Проще — на сервере, без токенов в выводе:
`node tools/token-scopes.mjs --project 1` — права, тип, срок и доступ к данным
по всем трём площадкам.

## 3. Threads: отдельный токен, другой домен

Threads **не выдаётся через Graph API Explorer** — другой домен
(`graph.threads.net`) и своя цепочка авторизации.

### Какие права нужны

| Право | Зачем |
|---|---|
| `threads_basic` | без него не отвечает ни один вызов |
| `threads_content_publish` | публикация |
| `threads_delete` | **снять пост** — без него проба форматов оставляет посты висеть, снимать приходится руками |

`threads_delete` добавили 13.09.2026: первая боевая проба опубликовала, а
удалить не смогла — «Application does not have permission for this action».

### 3А. Основной путь — кнопка «Подключить через Threads»

Один раз в кабинете Meta:

1. **Сценарии использования → Threads API → Персонализировать** → добавить
   права из таблицы выше (и `threads_keyword_search`, `threads_manage_insights`,
   `threads_read_replies`, `threads_manage_replies` — кнопка просит все).
2. **Threads API → Настройки**: «URL обратного вызова для перенаправления» —
   `https://smm.mycomputer.education/oauth/threads`. Threads **не сохраняет
   настройки, пока не заполнены все три адреса** (возврат, удаление приложения,
   удаление данных).
3. В панели в карточке **Threads** заполнить **ID приложения Threads** и
   **Секрет приложения Threads** (там же, Threads API → Настройки). ID
   приложения — **только в это поле**, не в «ID аккаунта».

Дальше — **«Подключить через Threads»** в карточке → окно Threads под
аккаунтом школы → согласие. Панель сама пишет токен и **настоящий ID аккаунта**,
а если какое-то право в окне согласия сняли — скажет об этом сразу.

### 3Б. Генератор маркеров — не использовать

**«Генератор маркеров пользователя» в кабинете Meta выдаёт фиксированный набор
прав** и не берёт добавленные в сценарий `threads_delete` и
`threads_keyword_search`. 13.09.2026 три токена подряд из генератора
публиковали, но не умели удалять. Ниже — как это было устроено, для истории.

1. `developers.facebook.com` → приложение → **Сценарии использования** →
   **Threads API** → **Персонализировать** → раздел разрешений →
   **«Добавить»** напротив каждого права из таблицы выше.
   Право, не добавленное в сценарий, в токен не попадёт, как ни жми дальше.
2. **Главная ловушка — сессия браузера.** Генератор открывает авторизацию в
   сессии Threads **текущего окна**. developers.facebook.com и threads.com
   должны быть открыты **в одном окне под аккаунтом академии**. Иначе ошибка
   **1349245 «The user has not accepted the invite»** — Meta проверяет не тот
   аккаунт, под которым принимали приглашение тестировщика.
3. Там же, в настройках сценария Threads, — **«Генератор маркеров
   пользователя»** → выпустить токен для аккаунта академии. В окне авторизации
   должны быть перечислены все права, включая удаление, — подтвердить.
4. Вписать токен в панель (раздел 4). Долгий токен живёт 60 дней.

### 3В. Запасной путь — OAuth-ссылка руками

Если кнопка в панели недоступна. Кнопка делает ровно это сама.

1. В приложении → продукт **Threads API** → Настройки:
   - **Redirect Callback URL**: `https://smm.mycomputer.education/oauth/threads`
     (должен быть https и совпадать до символа с адресом в шаге 3; принимать
     этот адрес панели не обязательно — код виден прямо в адресной строке),
   - права — все три из таблицы выше.
   Threads **не сохраняет настройки, пока не заполнены все три адреса**:
   возврат, удаление приложения, удаление данных.
2. В приложении Threads под аккаунтом «Мой компьютер»: Настройки → Аккаунт →
   **Доступ к Threads API** — включить.
3. Открыть в браузере, войдя под аккаунтом «Мой компьютер»:

```
https://threads.net/oauth/authorize?client_id=THREADS_APP_ID&redirect_uri=https://smm.mycomputer.education/oauth/threads&scope=threads_basic,threads_content_publish,threads_delete&response_type=code
```

   Разрешить → браузер уйдёт на адрес возврата, и **в строке адреса будет
   `?code=…`**. Скопировать код, отбросив хвост `#_`, если он есть.
   Код живёт считаные минуты — дальше сразу.

4. Обменять код на короткий токен (час жизни):

```
curl -X POST https://graph.threads.net/oauth/access_token -d client_id=THREADS_APP_ID -d client_secret=THREADS_APP_SECRET -d grant_type=authorization_code -d redirect_uri=https://smm.mycomputer.education/oauth/threads -d code=КОД
```

5. Обменять на долгий (60 дней):

```
curl "https://graph.threads.net/access_token?grant_type=th_exchange_token&client_secret=THREADS_APP_SECRET&access_token=КОРОТКИЙ_ТОКЕН"
```

6. Узнать ID аккаунта:

```
curl "https://graph.threads.net/v1.0/me?fields=id,username&access_token=ДОЛГИЙ_ТОКЕН"
```

   **Это не ID приложения.** В сентябре 2026 в поле «ID аккаунта» попал ID
   приложения Threads — проверка связи при этом проходила (она ходит на `me`),
   а публикация падала с «Object with ID … does not exist». Теперь «Проверить
   связь» сверяет ID и предупреждает жёлтым, если он не тот.

7. **Продление делать не нужно** — сторож панели продлевает токен Threads сам
   за две недели до смерти. Руками — только если сторож написал в журнал, что
   продлить не смог. Истёкший токен продлить уже нельзя, только выпустить заново.

```
curl "https://graph.threads.net/refresh_access_token?grant_type=th_refresh_token&access_token=ДОЛГИЙ_ТОКЕН"
```

### Проверить, что права попали в токен

У Threads **есть `debug_token`**, хотя в документации его нет (найден
13.09.2026), — спрашивать можно самим токеном:

```
curl "https://graph.threads.net/v1.0/debug_token?input_token=ТОКЕН&access_token=ТОКЕН"
```

Он отдаёт права, срок и доступ к данным. На сервере то же без токенов в выводе:
`node tools/token-scopes.mjs --project 1`. Проба боем с удалением:
`node tools/smoke-post.mjs --project 1 --platforms threads`.

## 4. Вписать в панель

`https://smm.mycomputer.education` → **Проекты** → проект → карточка площадки.
**При подключении кнопками токены и ID заполняются сами** — руками вписываются
только ключи приложений. Поля:

**Facebook**
- `ID страницы`, `Токен страницы` — кнопкой (вручную — из `GET /me/accounts`)
- `ID приложения`, `Секрет приложения` — руками, из настроек приложения. Нужны
  кнопке и сторожу (срок токена читается с ними)
- `ID конфигурации входа` — необязательно, см. раздел 2

**Instagram**
- `ID аккаунта`, `Токен страницы` — кнопкой «Подключить через Facebook»
  (вручную — `instagram_business_account.id` и тот же токен, что у Facebook)

**Threads**
- `ID аккаунта`, `Токен доступа` — кнопкой. Вписать ID руками можно, но при
  сохранении панель всё равно сверит его с площадкой и поправит; у академии
  `29062313960036757`. **Не ID приложения**
- `ID приложения Threads`, `Секрет приложения Threads` — руками, нужны кнопке

Смена токена сама выставляет дату его выпуска на сегодня. Если токен вписан
руками и выпущен раньше — дату поправить:
`node tools/set-account.mjs --project 1 --platform threads --token-issued <ISO>`
(срок Threads сторож читает у площадки, дата нужна только на случай, если она
не ответит).

Дальше в каждой карточке — **«Проверить связь»**. Успех выглядит так: Facebook
показывает название страницы, Instagram — имя пользователя, Threads — имя
пользователя. Пока не показал, публиковать бессмысленно.

Сохранённые секреты панель наружу не отдаёт: видно только хвост («…a41f»).
Пустое поле при сохранении означает «не менять» — прежнее значение остаётся.

## 5. Сроки: токен и доступ к данным

У токена Meta **два срока**, и сторож панели следит за обоими (раз в шесть
часов, плюс кнопка «Проверить токены»):

| | Что это | Чем лечится |
|---|---|---|
| **Срок токена** (`expires_at`) | токен перестаёт работать совсем | Threads — продлевается сам за 2 недели; Facebook/Instagram от кнопки — бессрочные |
| **Доступ к данным** (`data_access_expires_at`) | правило Meta: **90 дней без входа в приложение** — токен жив, но доступ к данным приложения закрывается | **войти кнопкой «Подключить через …»** — сам вход продлевает срок; «Применить» при этом нажимать не обязательно |

- Предупреждение приходит **за две недели** — точкой у раздела «Проекты», запиской
  в карточке и строкой в журнале, и **говорит, какой из двух сроков подходит**.
- **У Facebook доступ к данным не отслеживается** намеренно: права страниц
  (`pages_*`) документация Meta выводит из-под правила 90 дней. Токен общий с
  Instagram, так что предупреждение по карточке Instagram покрывает оба, и один
  вход лечит оба.
- Для прав Instagram и Threads документация про правило молчит — поэтому следим.
- 13.09.2026 у академии: Facebook/Instagram — токен бессрочный, доступ к данным
  до **12.12.2026**; Threads — токен до 12.11.2026 (продлится сам), доступ к
  данным до 12.12.2026. Проще всего раз в квартал нажимать обе кнопки.

## Что идёт не так чаще всего

| Симптом | Что на самом деле |
|---|---|
| Страницы нет в списке при выдаче токена | Instagram не переведён в Business или не связан со страницей — шаг 0 |
| `(#200) Requires pages_manage_posts` | Скоуп не отмечен при генерации; добавить права задним числом нельзя — токен перевыпустить |
| `instagram_business_account` в ответе отсутствует | Связка страницы и IG не доехала: пересвязать в Business Suite и подождать несколько минут |
| Instagram молча отвергает картинку | Прислан PNG. Контейнер принимает **только JPEG** — валидатор панели ловит это заранее |
| Постинг встал, ошибок нет | Протух токен или кончился доступ к данным — смотреть карточку проекта: сторож пишет, какой срок. Лечится кнопкой подключения |
| Threads публикует, но не удаляет | Токен выпущен генератором маркеров — у него нет `threads_delete`. Переподключить кнопкой |
| Threads: «Object with ID … does not exist» при публикации | В «ID аккаунта» вписан ID приложения. Сохранить карточку — панель сама поставит настоящий |
| Экран выбора страницы не открылся после входа Facebook | Браузер держит старую версию панели — Ctrl+F5 и войти заново |
| `redirect_uri mismatch` (Threads или Facebook) | Адрес возврата отличается от вписанного в настройках хотя бы слэшем |
| Площадка не забрала медиа | `PUBLIC_BASE_URL` недоступен снаружи: сети **сами качают файл по ссылке** |

## Про App Review

Для этих трёх площадок он **не нужен**, пока публикуем в свои аккаунты и у
аккаунтов есть роль в приложении. Режим разработки — штатный рабочий режим для
такого сценария. Review понадобится, только если панель начнёт публиковать от
имени чужих аккаунтов (продукт для агентств). `threads_keyword_search` в
режиме разработки кнопка выдаёт, но без Review поиск видит только посты самого
аккаунта — для трендов по чужим постам Review всё равно нужен.

## Версия Graph API

Facebook и Instagram ходят на одну версию Graph API — `v26.0` (с 13.09.2026,
до этого `v21.0`, которая отключается 21.01.2027). Номер задан в одном месте,
`src/platforms/graph.js`; тест не даст вписать его в код где-то ещё. Версия
Meta живёт около двух лет — сроки смотреть в
[списке версий](https://developers.facebook.com/docs/graph-api/changelog/versions).

Переезд на следующую:

1. Прочитать списки изменений Graph API и Instagram Platform за пропущенные
   версии.
2. На сервере сверить ответы старой и новой версии на боевых доступах —
   только чтение, токены не печатаются:
   `node tools/graph-version-probe.mjs --project 1 --to vNN.0`
3. Поменять номер в `src/platforms/graph.js`, прогнать тесты.
4. Боевая проба всех форматов с удалением (`tools/smoke-post.mjs`).

У Threads версия своя (`v1.0`, другой нет) и в этот порядок не входит.
