# Подключение площадок

Порядок выбран так, чтобы ожидание чужих проверок шло фоном, а не блокировало
работу. Всё, что ниже, делается в кабинетах вручную — из кода это недоступно.

Instagram, Facebook и Threads расписаны по шагам отдельно:
[токены-meta.md](токены-meta.md) — там же сказано, куда вписывать значения
(карточка проекта в панели, а не `.env`).

## 0. Сразу: подать TikTok на аудит

Аудит идёт 2–4 недели, и это единственное, что нельзя обойти. **Пока он не
пройден, публикация принудительно приватная** (`SELF_ONLY`) и не более чем для
пяти пользователей в сутки — режим разработки тут не спасает, в отличие от Meta.

1. `developers.tiktok.com` → зарегистрировать приложение.
2. Запросить **Content Posting API**, скоуп `video.publish`.
3. Подать на аудит. Документов юрлица не требуют.
4. Заодно **верифицировать домен** `smm.mycomputer.education` — без этого
   TikTok не станет забирать файл по ссылке, и останется только прямая заливка.

Что чаще всего отклоняют: интерфейс не показывает имя и аватар автора перед
публикацией и не спрашивает подтверждение музыки. У нас `creator_info` в
адаптере есть — композер обязан выводить эти данные до кнопки публикации.

В `.env`: `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`, `TIKTOK_ACCESS_TOKEN`,
`TIKTOK_REFRESH_TOKEN`. После аудита — `TIKTOK_PRIVACY=PUBLIC_TO_EVERYONE`
и `TIKTOK_DOMAIN_VERIFIED=true`.

## 1. Telegram — десять минут, без проверок

1. `@BotFather` → `/newbot` → получить токен.
2. Добавить бота **администратором канала** с правом публикации.
3. В `.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (`@имя_канала` или числовой id).

Проверка: в шапке планировщика нажать значок Telegram — покажет имя бота и канал.

Отдельный бот от того, что шлёт заявки с сайтов: смешивать уведомления и
контент — значит однажды уронить оба разом одной правкой токена.

## 2. Threads

1. Включить доступ к Threads API у аккаунта.
2. Приложение с use-case Threads, получить долгоживущий токен.
3. В `.env`: `THREADS_USER_ID`, `THREADS_ACCESS_TOKEN`.

**Токен живёт 60 дней.** Продлевать заранее — иначе постинг встанет молча.

## 3. Meta: Facebook и Instagram — одно приложение на обе

1. Instagram перевести в **Professional (Business)** и связать со **страницей**
   Facebook. С личного профиля API не публикует.
2. `developers.facebook.com` → приложение типа Business.
3. Добавить свой аккаунт в роли приложения (Admin/Developer).
4. Разрешения: `pages_manage_posts`, `pages_read_engagement`,
   `instagram_basic`, `instagram_content_publish`.
5. Получить токен страницы, обменять на долгоживущий, а лучше сразу завести
   **system user** в Business Manager — его токен бессрочный.

**App Review, скорее всего, не нужен:** приложение в режиме разработки работает
для аккаунтов, у которых есть роль в этом же приложении. Проверять это надо
первым делом — если сработает, экономит недели.

В `.env`: `META_APP_ID`, `META_APP_SECRET`, `FACEBOOK_PAGE_ID`,
`FACEBOOK_PAGE_TOKEN`, `INSTAGRAM_USER_ID`.

## Что ломается чаще всего

| Симптом | Причина |
|---|---|
| Instagram отвергает картинку без внятной ошибки | Прислали PNG. Контейнер принимает только JPEG (валидатор это ловит заранее) |
| Постинг встал молча, ошибок нет | Протух токен: Threads и страница Facebook — 60 дней |
| TikTok опубликовал, но поста никто не видит | Аудит не пройден, режим `SELF_ONLY` |
| Пост ушёл в Telegram двумя сообщениями | Подпись длиннее 1024 символов |
| Площадка не смогла забрать медиа | `PUBLIC_BASE_URL` недоступен снаружи или домен не верифицирован (TikTok) |
