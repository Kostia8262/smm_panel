# Токены Instagram, Facebook и Threads — по шагам

Инструкция под аккаунты **«Мой компьютер»** (академия). Всё делается руками в
кабинетах Meta; из кода это недоступно. Занимает вечер, если аккаунты уже
приведены в порядок (шаг 0).

Важное про место хранения: **`.env` для площадок больше не нужен**. Токены
вписываются в панели — «Площадки» → карточка проекта → поля. В базе они лежат
шифротекстом, ключ — `data/secret.key` рядом с базой.

Три площадки — **два разных токена**:

| Площадка | Откуда токен | Срок |
|---|---|---|
| Facebook | токен страницы (Graph API) | 60 дней, у system user — бессрочный |
| Instagram | **тот же токен страницы** | тот же |
| Threads | свой OAuth, свой домен `graph.threads.net` | 60 дней, продлевается |

---

## 0. Привести аккаунты в состояние, при котором API вообще работает

Без этого шага всё остальное упрётся в невнятные ошибки.

1. **Instagram «Мой компьютер» → Professional (Business).**
   Приложение Instagram → Настройки → Тип аккаунта → «Переключиться на
   профессиональный» → **Бизнес** (Creator тоже публикует, но с Business
   меньше сюрпризов с правами).
2. **Связать Instagram со страницей Facebook «Мой компьютер».**
   Проще из Meta Business Suite: `business.facebook.com` → Настройки →
   Аккаунты → Аккаунты Instagram → Добавить → связать со страницей.
   С личного профиля Facebook API не публикует вовсе — нужна именно **страница**.
3. **Бизнес-портфель (Business Manager).** Страница и Instagram должны лежать
   в одном портфеле — иначе системный пользователь из шага 2Б их не увидит.

Проверка шага: в Business Suite видно и страницу, и Instagram под одним
портфелем, и на обоих у вас роль администратора.

## 1. Приложение в кабинете разработчика

1. `developers.facebook.com` → «Мои приложения» → **Создать приложение**.
2. Тип — **Business** (формулировки Meta меняет; нужен тот тип, где доступны
   «Страницы» и «Instagram»).
3. Название — например `MyComputer SMM`. Почта — рабочая: на неё придут письма
   о протухании токенов и о нарушениях.
4. **Роли → Разработчики/Администраторы**: добавить свой аккаунт, если его там
   нет. Это ключ ко всему — **пока приложение в режиме разработки, оно работает
   для аккаунтов, у которых есть роль в нём же**. Публикуем в свои аккаунты →
   проверка Meta не нужна.
5. Продукты → добавить **Instagram** (Instagram Graph API) и, для шага 3,
   **Threads API** (это отдельный use case).
6. Настройки → Основное: записать **ID приложения** и **Секрет приложения** —
   панель ими читает срок жизни токена (`debug_token`).

## 2. Facebook + Instagram: один токен на обе площадки

Два пути. **А** — за десять минут, токен на 60 дней. **Б** — дольше, но
бессрочно. Разумно сделать А (убедиться, что всё работает), а потом не
полениться и перевести на Б.

### 2А. Быстрый путь — Graph API Explorer

1. `developers.facebook.com/tools/explorer`.
2. Сверху выбрать своё приложение, тип токена — **User Token**.
3. Добавить разрешения (каждое через «Add a Permission»):
   - `pages_show_list`
   - `pages_manage_posts`
   - `pages_read_engagement`
   - `instagram_basic`
   - `instagram_content_publish`
   - `business_management`
4. **Generate Access Token** → в окне входа отметить страницу «Мой компьютер»
   и связанный Instagram. Если страницы в списке нет — вернуться к шагу 0.
5. Узнать ID страницы и её токен — запрос `GET /me/accounts`. В ответе у нужной
   страницы: `id` — это **ID страницы**, `access_token` — токен страницы
   (пока короткий).

6. Обменять на долгоживущий. Сначала пользовательский токен:

```
curl "https://graph.facebook.com/v21.0/oauth/access_token?grant_type=fb_exchange_token&client_id=APP_ID&client_secret=APP_SECRET&fb_exchange_token=КОРОТКИЙ_USER_TOKEN"
```

   Затем **повторить `/me/accounts` уже с долгоживущим пользовательским
   токеном** — выданный так токен страницы срока не имеет (живёт, пока не
   сменён пароль и не отозваны права):

```
curl "https://graph.facebook.com/v21.0/me/accounts?access_token=ДОЛГИЙ_USER_TOKEN"
```

7. Узнать ID Instagram-аккаунта:

```
curl "https://graph.facebook.com/v21.0/PAGE_ID?fields=instagram_business_account&access_token=PAGE_TOKEN"
```

   В ответе `instagram_business_account.id` — это **ID аккаунта Instagram**
   (числовой, обычно начинается с 17…; это не имя пользователя).

### 2Б. Правильный путь — системный пользователь (токен без срока)

Смысл: токен привязан не к живому человеку, а к служебной учётке бизнеса.
Смена вашего пароля его не рвёт, и «постинг встал молча через 60 дней» не
случается.

1. `business.facebook.com` → **Настройки бизнеса** → Пользователи →
   **Системные пользователи** → Добавить. Имя — `smm-panel`, роль —
   **Администратор**.
2. У созданного пользователя → **Добавить активы**:
   - Страницы → «Мой компьютер» → **полный доступ к контенту**,
   - Аккаунты Instagram → «Мой компьютер» → полный доступ,
   - Приложения → `MyComputer SMM` → полный доступ.
3. **Создать новый токен** → выбрать приложение → **срок действия «Никогда»** →
   отметить скоупы: `pages_manage_posts`, `pages_read_engagement`,
   `instagram_basic`, `instagram_content_publish`, `business_management`.
4. **Токен показывается ровно один раз.** Скопировать сразу и положить туда же,
   где остальные доступы проекта.
5. ID страницы и ID Instagram берутся теми же двумя запросами из 2А (шаги 5 и 7),
   уже с этим токеном.

### Проверить токен до того, как вписывать

```
curl "https://graph.facebook.com/v21.0/debug_token?input_token=PAGE_TOKEN&access_token=APP_ID|APP_SECRET"
```

Смотреть три вещи: `is_valid: true`; `expires_at: 0` — бессрочный (то, что
и нужно от системного пользователя); в `scopes` присутствует
`instagram_content_publish`.

## 3. Threads: отдельный токен, другой домен

Threads **не выдаётся через Graph API Explorer** — только полноценный OAuth.
И домен API у него свой: `graph.threads.net`.

1. В приложении → продукт **Threads API** → Настройки:
   - **Redirect Callback URL**: `https://smm.mycomputer.education/oauth/threads`
     (должен быть https и совпадать до символа с адресом в шаге 3; принимать
     этот адрес панели не обязательно — код виден прямо в адресной строке),
   - скоупы: `threads_basic`, `threads_content_publish`.
2. В приложении Threads под аккаунтом «Мой компьютер»: Настройки → Аккаунт →
   **Доступ к Threads API** — включить.
3. Открыть в браузере, войдя под аккаунтом «Мой компьютер»:

```
https://threads.net/oauth/authorize?client_id=THREADS_APP_ID&redirect_uri=https://smm.mycomputer.education/oauth/threads&scope=threads_basic,threads_content_publish&response_type=code
```

   Разрешить → браузер уйдёт на адрес возврата, и **в строке адреса будет
   `?code=…`**. Скопировать код, отбросив хвост `#_`, если он есть.
   Код живёт считаные минуты — дальше сразу.

4. Обменять код на короткий токен (час жизни):

```
curl -X POST https://graph.threads.net/oauth/access_token -d client_id=THREADS_APP_ID -d client_secret=THREADS_APP_SECRET -d grant_type=authorization_code -d redirect_uri=https://smm.mycomputer.education/oauth/threads -d code=КОД
```

5. Обменять на долгий (60 дней):

```
curl "https://graph.threads.net/access_token?grant_type=th_exchange_token&client_secret=THREADS_APP_SECRET&access_token=КОРОТКИЙ_ТОКЕН"
```

6. Узнать ID аккаунта:

```
curl "https://graph.threads.net/v1.0/me?fields=id,username&access_token=ДОЛГИЙ_ТОКЕН"
```

7. **Продление** (делать между 25-м и 55-м днём; раньше суток от выдачи Threads
   продлевать отказывается):

```
curl "https://graph.threads.net/refresh_access_token?grant_type=th_refresh_token&access_token=ДОЛГИЙ_ТОКЕН"
```

## 4. Вписать в панель

`https://smm.mycomputer.education` → **Площадки** → проект → карточка площадки.
Поля ровно эти:

**Facebook**
- `ID страницы` — из `GET /me/accounts`
- `Токен страницы` — из шага 2А.6 или 2Б.3
- `ID приложения`, `Секрет приложения` — из настроек приложения (нужны, чтобы
  панель видела срок жизни токена)

**Instagram**
- `ID аккаунта` — `instagram_business_account.id`
- `Токен страницы` — **тот же самый**, что у Facebook

**Threads**
- `ID аккаунта` — из `GET /me`
- `Токен доступа` — долгий токен из шага 3.5

Дальше в каждой карточке — **«Проверить связь»**. Успех выглядит так: Facebook
показывает название страницы, Instagram — имя пользователя, Threads — имя
пользователя. Пока не показал, публиковать бессмысленно.

Сохранённые секреты панель наружу не отдаёт: видно только хвост («…a41f»).
Пустое поле при сохранении означает «не менять» — прежнее значение остаётся.

## Что идёт не так чаще всего

| Симптом | Что на самом деле |
|---|---|
| Страницы нет в списке при выдаче токена | Instagram не переведён в Business или не связан со страницей — шаг 0 |
| `(#200) Requires pages_manage_posts` | Скоуп не отмечен при генерации; добавить права задним числом нельзя — токен перевыпустить |
| `instagram_business_account` в ответе отсутствует | Связка страницы и IG не доехала: пересвязать в Business Suite и подождать несколько минут |
| Instagram молча отвергает картинку | Прислан PNG. Контейнер принимает **только JPEG** — валидатор панели ловит это заранее |
| Постинг встал, ошибок нет | Протух токен. Лечится системным пользователем (Facebook/Instagram) и продлением (Threads) |
| Threads: `redirect_uri mismatch` | Адрес возврата отличается от вписанного в настройках хотя бы слэшем |
| Площадка не забрала медиа | `PUBLIC_BASE_URL` недоступен снаружи: сети **сами качают файл по ссылке** |

## Про App Review

Для этих трёх площадок он **не нужен**, пока публикуем в свои аккаунты и у
аккаунтов есть роль в приложении. Режим разработки — штатный рабочий режим для
такого сценария. Review понадобится, только если панель начнёт публиковать от
имени чужих аккаунтов (продукт для агентств) или если захочется
`threads_keyword_search` для трендов.
